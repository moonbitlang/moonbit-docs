# E4222

Compiler diagnostic name: `invalid_lexscan_target`.

Invalid lexical matching target.

`lexmatch` accepts an in-memory `String`, `StringView`, `Bytes`, or `BytesView`.
`lexscan` accepts `@lexbuf.StringScanner`, `@lexbuf.Lexbuf`, and
`@lexbuf.AsyncLexbuf` for text, or `@lexbuf.BytesScanner`, `@lexbuf.BytesLexbuf`,
and `@lexbuf.AsyncBytesLexbuf` for bytes. It also accepts custom types that
implement `@lexbuf.Scannable` or `@lexbuf.BytesScannable`.

A plain `String`, `StringView`, `Bytes`, or `BytesView` is not a valid `lexscan`
target. Use `lexmatch` for one in-memory match, or construct a `StringScanner`
or `BytesScanner` to maintain a cursor between scans. Merely defining methods
with the same names as a scanning trait does not implement that trait.

## Erroneous example

```moonbit
///|
pub fn scan_text(text : String) -> Unit {
  lexscan text with longest {
    _ => ()
  }
}
```

## Suggestion

Use `lexmatch` with text or bytes, or use one of the supported scanner types for
`lexscan`. For a custom in-memory scanner, implement the appropriate scanning
trait; see [custom scanners](https://docs.moonbitlang.com/en/latest/language/fundamentals.html#custom-scanners).

```moonbit
///|
pub fn match_text(text : String) -> Unit {
  lexmatch text with longest {
    _ => ()
  }
}
```
