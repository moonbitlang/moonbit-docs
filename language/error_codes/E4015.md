# E4015

Type has no method with the specified name.

## Erroneous Example

```moonbit
///|
pub fn shout() -> String {
  "hey".upper()
}
```

The above example tries to call an inexistent method `upper()`
on a string literal, giving the following error on line 1:

```none
Type String has no method upper.
```

## Suggestion

This is usually a typo or a misunderstanding of the methods available.
Please make sure to use the correct method name:

```moonbit
///|
pub fn shout() -> String {
  "hey".to_upper()
}
```

If the missing method belongs to a trait, an `impl Trait for Type` declaration
does not by itself guarantee that the method can be called with dot syntax.
Call it explicitly as `Trait::method(value, ...)`, or attach the method with
`extend Type with Trait::{method}`. Use `pub extend` if callers in other packages
should also be able to use dot syntax. See
[attaching trait methods with `extend`](https://docs.moonbitlang.com/en/latest/language/methods.html#attaching-trait-methods-with-extend).

For example, implementing `Render` alone does not make `badge.render()` available:

```moonbit
///|
pub(open) trait Render {
  fn render(Self) -> String
}

///|
pub(all) struct Badge(String)

///|
pub impl Render for Badge with render(self) {
  self.0
}

///|
pub fn show_badge(badge : Badge) -> String {
  badge.render()
}
```

Attach `render` explicitly to allow the dot call:

```moonbit
///|
pub(open) trait Render {
  fn render(Self) -> String
}

///|
pub(all) struct Badge(String)

///|
pub impl Render for Badge with render(self) {
  self.0
}

///|
pub extend Badge with Render::{render}

///|
pub fn show_badge(badge : Badge) -> String {
  badge.render()
}
```
