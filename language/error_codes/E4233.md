# E4233

Compiler diagnostic name: `regex_execution_limit_exceeded`.

The regex match exceeds a compilation resource limit and cannot use the runtime
fallback. This is a compile-time error, not a timeout while matching input.

## Erroneous example

```moonbit
///|
pub fn matches(input : @lexbuf.Lexbuf) -> Bool {
  lexscan input {
    re"^[01]*1[01]{20}$" => true
    _ => false
  }
}
```

This streaming scan exceeds the compilation limit and cannot use runtime
fallback. It matches binary strings whose twenty-first character from the end
is `1`.

## Suggestion

Simplify the regex patterns or split the operation into smaller matches.
Preserve the intended matching order and captures when splitting a match.

If rejected binary input may be discarded, scan the binary digits with a simpler
pattern, then check the character position directly. This preserves the boolean
result, but not the scanner position on failure: the regex case consumes the
binary input before its body checks the position. For example, `"1"` returns
`false` after consuming the input, whereas the original catch-all would leave
it untouched. Do not use this rewrite when another scanner must retry that input.

```moonbit
///|
pub fn matches(input : @lexbuf.Lexbuf) -> Bool {
  lexscan input {
    re"^[01]+$" as bits =>
      bits.length() >= 21 && bits[bits.length() - 21] == '1'
    _ => false
  }
}

///|
test {
  for (text, expected) in [
    ("100000000000000000000", true),
    ("000000000000000000000", false),
    ("1", false),
    ("10000000000000000000x", false),
  ] {
    let chunks = [text].iter()
    let input = @lexbuf.Lexbuf::from_fn(() => chunks.next())
    assert_eq(matches(input), expected)
  }
}

///|
test "rejected binary input is consumed" {
  let chunks = ["1"].iter()
  let input = @lexbuf.Lexbuf::from_fn(() => chunks.next())
  assert_false(matches(input))
  let at_end = lexscan input {
    re"^." => false
    _ => true
  }
  assert_true(at_end)
}
```

The diagnostic reports the resource limit that was exceeded. Limits may change
between compiler versions, so do not rely on a particular threshold.

When runtime fallback is available, the compiler can instead accept the match
and report [E0097](https://docs.moonbitlang.com/en/latest/language/error_codes/E0097.html) if that warning is enabled.
