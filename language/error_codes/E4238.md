# E4238

Compiler diagnostic name: `unknown_constr_pat_on_error`.

The pattern `Type::..` cannot be used when matching or catching a value of type
`Error`. This pattern handles future constructors of a concrete
[`#non_exhaustive`](https://docs.moonbitlang.com/en/latest/language/attributes/non_exhaustive.html) type, not the open set of
suberror types represented by `Error`.

## Erroneous example

```moonbit
///|
#non_exhaustive
pub(all) suberror ParseError {
  InvalidInput
}

///|
pub fn is_parse_error(error : Error) -> Bool {
  match error {
    ParseError::InvalidInput => true
    ParseError::.. => true
    _ => false
  }
}
```

## Suggestion

Use `Type::_` to match all constructors of one suberror type, and `_` to handle
other error types. To handle known constructors separately, place their cases
before `Type::_`.

```moonbit
///|
#non_exhaustive
pub(all) suberror ParseError {
  InvalidInput
}

///|
pub fn is_parse_error(error : Error) -> Bool {
  match error {
    ParseError::_ => true
    _ => false
  }
}
```
